AZ-900 · Reference

Cheat Sheet

Every term and service from this course, restated as one short, memorable definition each. Built for a last-pass skim right before the exam — read top to bottom once, then jump to whatever domain feels shakiest.

How to use this on exam day Skim once fully (~10 min), then re-skim just the bolded term names, covering the definitions — if you can say the definition from the name alone, you're done with that line.

Domain 1 · Cloud concepts 25–30%

Shared responsibility model
One rule, always true: you always own data, identities, devices, and access; Microsoft always owns the physical datacenter. Everything in between (OS, runtime, app code) shifts toward Microsoft as you move IaaS → PaaS → SaaS.
Public cloud
Multi-tenant, shared infrastructure — cheapest, fastest to deploy, no hardware ownership.
Private cloud
Single-tenant, dedicated infrastructure (can still be provider-hosted) — for compliance, control, or predictable performance.
Hybrid cloud
Public + private/on-prem, connected — regulated data stays on-prem, workloads burst to cloud.
CapEx vs. OpEx
CapEx: buy hardware upfront, depreciate over years. OpEx (consumption-based): pay only for what you use. The cloud's pitch is shifting CapEx to OpEx.
High availability
Keeps running and meets its SLA despite a failure.
Scalability
Capacity grows/shrinks automatically with demand.
Reliability
Recovers and keeps functioning consistently over time.
Predictability
You can forecast cost and performance in advance.
Manageability
Deploying/monitoring/maintaining resources is easy at scale.
IaaS (Infrastructure as a Service)
You manage the OS and everything above it (e.g. Azure VMs). Full control, most overhead.
PaaS (Platform as a Service)
Gives you the building blocks (like Azure App Service or Azure SQL Database) to code, host, and manage your own custom applications without worrying about underlying operating systems or hardware.
SaaS (Software as a Service)
Gives you a complete, ready-to-run application (like Microsoft 365 or Dynamics 365) accessed via a browser where you only manage your data and user settings.
Serverless
A step beyond PaaS — zero capacity to provision, billed strictly per execution (e.g. Azure Functions), not a running app-service plan.

Domain 2 · Architecture & hierarchy 35–40%

Management group
Governs multiple subscriptions at once — the top of the resource hierarchy.
Subscription
Billing and scale boundary. Sits below a management group, above resource groups.
Resource group
Lifecycle and RBAC/Policy container for related resources, inside a subscription. Purely organizational — no direct AWS/GCP equivalent.
Resource
A specific deployed instance — one VM, one storage account, etc.
Tenant
Your organization's Microsoft Entra ID directory — sits above subscriptions, not inside the resource hierarchy itself. One tenant can contain many subscriptions.
RBAC/Policy inheritance
Assignments at a higher scope (management group → subscription → resource group → resource) are inherited downward.
Region
A geographic area with one or more datacenters.
Datacenter
The physical facility — power, cooling, physical security — underlying a region. Microsoft always owns this layer, regardless of service type.
Availability zone
A physically separate datacenter within a region, synchronously replicated — protects against losing one datacenter.
Region pair
Two regions in the same geography, asynchronously linked for disaster recovery and sequenced platform updates — protects against losing an entire region.
Sovereign region
A physically and logically isolated Azure instance for legal/compliance reasons (e.g. Azure Government) — not about physical failure, about isolation from global Azure.

Domain 2 · Compute 35–40%

Virtual Machines (VMs)
IaaS compute — you manage the OS and above.
Virtual Machine Scale Sets
A group of identical VMs that auto-scales with demand.
Availability set
Groups VMs across fault/update domains for resilience — manually placed, no auto-scaling (unlike scale sets).
Azure Container Instances (ACI)
Run a single container with no VM to manage.
Azure Kubernetes Service (AKS)
Managed Kubernetes — you manage orchestration config, not the control plane.
Azure Functions
Serverless — just your code, billed per execution.
Azure App Service
PaaS web app hosting — just your app code.
Azure Virtual Desktop
Streams a full virtual desktop to end users.
Azure Batch
Runs large-scale parallel/batch compute jobs across a managed pool of VMs.

Domain 2 · Networking 35–40%

Virtual Network (VNet)
Your private, isolated address space in Azure.
Subnet
A segment of a VNet's address space, for organization and security boundaries.
VNet peering
Private VNet-to-VNet connectivity, off the public internet.
VPN Gateway
Encrypted tunnel connecting on-premises to Azure over the public internet.
ExpressRoute
Dedicated private circuit connecting on-premises to Azure, off the public internet.
Azure DNS
Resolves domain names to IP addresses.
Public endpoint
Internet-reachable address for a service.
Private endpoint
Brings a PaaS service's traffic inside your VNet via a private IP — no public internet exposure. Applies broadly (storage, SQL, Key Vault, etc.), not just one service.
Public IP address
A static, internet-reachable address you assign to a resource (e.g. a load balancer or VM).
Network security group (NSG)
Allow/deny traffic rules filtering inbound/outbound traffic at the subnet or NIC level.
Azure Load Balancer
Distributes traffic across VMs at the network layer (L4), within a region.
Azure Front Door
Global, application-layer (L7) entry point — load balancing, routing, and acceleration across regions.

Domain 2 · Storage 35–40%

Storage account
The top-level container you create in Azure Storage — a namespace for your blobs, files, tables, and queues, with its own redundancy/tier/security settings.
Blob Storage
Unstructured objects over HTTP/HTTPS.
Azure Files
Mountable SMB/NFS file shares.
Table Storage
NoSQL key-value store.
Queue Storage
App-to-app messaging queue.
Access tiers (Hot / Cool / Cold / Archive)
Control how often you access data — hottest is most expensive to store, cheapest to read; Archive is cheapest to store, hours of retrieval latency. Independent from redundancy — don't confuse the two axes.
LRS (locally redundant storage)
3 synchronous copies, one datacenter. Least resilient.
ZRS (zone-redundant storage)
3 synchronous copies, spread across availability zones in one region.
GRS (geo-redundant storage)
LRS + one async copy in the paired region.
GZRS (geo-zone-redundant storage)
ZRS + one async copy in the paired region — widest protection.
Secure transfer required (HTTPS-only)
Storage account setting that rejects plain HTTP requests.
AzCopy
Command-line, scriptable bulk copy of blobs/files.
Azure Storage Explorer
Desktop GUI equivalent of AzCopy.
Azure File Sync
Hybrid caching — on-prem server caches hot files, full data lives in Azure Files.
Azure Migrate
Assesses and migrates whole on-prem servers.
Azure Data Box
Offline, shippable appliance for bulk data transfer.

Domain 2 · Identity, access & security 35–40%

Microsoft Entra ID
Identity directory — users, groups, app registrations. Formerly "Azure Active Directory" / "Azure AD" — the old name is a frequent distractor.
Microsoft Entra Domain Services
Managed, classic AD-compatible directory (domain join, LDAP, Group Policy) for legacy apps — not a replacement for Entra ID.
Azure RBAC
Role assignment = security principal + role definition + scope. Controls who can do what.
Microsoft Entra Conditional Access
Rule-based access policy that requires extra checks (e.g. MFA) or blocks sign-in based on context — risk level, device state, location — rather than applying the same rule to everyone always.
External identities
Partners/guests sign in with their own identity provider instead of a new account in your tenant.
Single sign-on (SSO)
Sign in once, access many apps.
Multifactor authentication (MFA)
A second verification factor beyond the password.
Passwordless authentication
Sign in with no password at all (e.g. Windows Hello, authenticator app).
Zero Trust
"Never trust, always verify" — no implicit trust from network location, verify explicitly for every request.
Defense-in-depth
Layered controls across network, identity, app, and data — how Zero Trust gets implemented in practice.
Microsoft Defender for Cloud
Scores and hardens your security posture across your resources.
Azure Key Vault
Centralized, managed store for secrets, keys, and certificates — apps fetch them at runtime instead of hard-coding credentials.

Domain 3 · Cost management 30–35%

Pricing calculator
Estimate cost for a hypothetical configuration before you deploy it.
Azure Cost Management
Analyze actual spend, set budgets and alerts, after resources are already running.
Tags
Metadata for cost allocation, filtering, and automation.

Domain 3 · Governance & compliance 30–35%

Azure Policy
Enforces/audits resource configuration rules, regardless of who deployed the resource. Distinct from RBAC (who can act).
Resource lock
Blocks delete (CanNotDelete) or delete+edit (ReadOnly) on a resource — independent of RBAC role. Even an Owner is blocked until the lock is removed.
Azure Blueprints
Packages a repeatable set of resources, policies, and role assignments together to stamp out compliant environments — broader than a single Policy definition.
Microsoft Purview
Unified data map, catalog, classification, and lineage across your data estate — governance/compliance, not resource configuration.

Domain 3 · Deployment & management tooling 30–35%

Azure portal
Web-based graphical UI for managing all Azure resources.
Azure Cloud Shell
Browser-based, pre-authenticated shell — zero install.
Azure CLI / Azure PowerShell
Same capabilities as Cloud Shell, installed and run locally instead.
Azure Resource Manager (ARM)
The underlying deployment/management engine and API that every tool (portal, CLI, templates) ultimately calls — not a UI itself.
ARM templates
Native declarative infrastructure-as-code format, written in JSON.
Bicep
Friendlier authoring language that compiles down to the same ARM JSON templates — same engine, easier syntax.
Azure Arc
Extends Azure's management plane (Policy, RBAC, tags) to servers and Kubernetes clusters running on-premises or in other clouds.

Domain 3 · Monitoring 30–35%

Azure Advisor
Proactive best-practice recommendations across cost, security, reliability, performance. Answers "what should I change?"
Azure Service Health
Is Azure itself (the platform) having an issue affecting your specific resources? Personalized, unlike the generic public Azure Status page.
Azure Monitor
Collects your resources' own metrics/logs and drives alerts. Answers "is my resource broken?"
↳ Log Analytics
KQL queries over logs collected by Azure Monitor.
↳ Application Insights
App-level performance telemetry, part of Azure Monitor.
↳ Alerts
Threshold-based automated notifications, part of Azure Monitor.

The recurring exam traps

Tool-boundary pairs the exam loves to test
  • Pricing calculator (before deploying) vs. Cost Management (after, actual spend).
  • Azure Policy (what configuration is allowed) vs. RBAC (who can act) vs. resource lock (blocks delete/edit regardless of role).
  • Azure Advisor (what should I improve?) vs. Service Health (is the platform broken?) vs. Monitor (is my resource broken?).
  • Access tiers (how often you access data) vs. redundancy (how many copies, where).
  • VPN Gateway (over the public internet) vs. ExpressRoute (dedicated private circuit).
  • Microsoft Entra ID (identities live here) vs. Azure RBAC (permissions get assigned here).
