Generative AI & Agents with Foundry

The heaviest domain on the exam. Two halves: building generative apps (deploy → RAG → workflows → evaluate → ship), then building agents on top of that same foundation (roles → tools → memory → orchestration).

Build generative applications with Foundry

The build loop, in order:

StepWhat you do
1. DeployDeploy an LLM, small model, code model, or multimodal model to a Foundry project
2. ConnectConfigure the application to connect to the Foundry project (endpoint + credential)
3. GroundImplement RAG so answers cite your data instead of hallucinating
4. OrchestrateDesign workflows, tool-augmented flows, and multistep reasoning pipelines
5. EvaluateScore outputs for fabrication, relevance, quality, and safety — not just spot-check
6. IntegrateWire it into the app via Foundry SDKs and connectors

The client shape (Python, current Foundry API) — recognize each piece, don't memorize it:

from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient

project = AIProjectClient(
    endpoint="https://my-resource.ai.azure.com/api/projects/my-project",
    credential=DefaultAzureCredential(),   # keyless — ties to D1's security controls
)
openai = project.get_openai_client()
response = openai.responses.create(
    model="gpt-5-mini",                    # your deployment name, not a raw model file
    input="Summarize the grounded context below in one sentence.",
)
print(response.output_text)
Evaluation isn't optional AI-103 expects you to know evaluation as a first-class build step: detecting fabrication (made-up facts), scoring relevance and quality, and checking safety — before an app ships, and continuously after.

Build agents with Foundry

An agent is a model plus everything it needs to act on its own: a defined role, tools, memory, and knowledge.

Building blockWhat it defines
Role & goalWhat the agent is for and what "done" looks like
Conversation-trackingHow the agent remembers earlier turns (its memory)
Tool schemaThe functions/APIs the agent is allowed to call, and their contracts
Knowledge integrationRetrieval, search, or content-understanding sources the agent can ground on

Beyond a single agent, AI-103 tests orchestration:

PatternWhen
Single agentOne role is enough to complete the task end to end
Orchestrated multi-agentDifferent specialized agents hand off work to each other
Autonomous / semi-autonomous with safeguardsThe agent acts on its own but under approval-flow controls (D1's governance)
Exam cue "Multiple specialized roles collaborate on one task" → orchestrated multi-agent. "One assistant plans, calls an API, and composes a result" → a single well-tooled agent. Once deployed, agents still need monitoring, behavior evaluation, and error analysis — the same discipline as models.

Optimize and operationalize generative AI systems

TechniqueWhat it improves
Prompt engineering & parameter tuningGeneration behavior (temperature, top-p, instructions)
Reflection / chain-of-thought evaluation / self-critiqueThe model checking and improving its own intermediate reasoning
Observability (tracing, token analytics, safety signals, latency)Understanding what's happening in production, not just at deploy time
Orchestrating multiple models / hybrid rules enginesCombining strengths — e.g. a cheap model routes, an expensive one answers hard cases
