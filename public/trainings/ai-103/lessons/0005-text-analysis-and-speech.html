Text Analysis & Speech

Two related skills: pulling structured meaning out of text (with either a language model or a purpose-built service), and moving between speech and text for agentic, voice-driven experiences.

Apply language model text analysis

TaskHow you build it
Extract entities, topics, summaries, structured JSONGenerative prompting or Azure Language in Foundry Tools
Detect sentiment, tone, safety issues, sensitive contentConfigure detection via Azure Language / content-safety signals
Translate text between languagesAzure Translator in Foundry Tools or an LLM-powered translation flow
Customize output for a domain task (e.g. compliance summarization)Prompt/instruction customization on top of the base extraction capability
Two doors, same outcome Text analysis on AI-103 can come from a purpose-built service (Azure Language: fast, structured, no prompt engineering) or from generative prompting against an LLM (flexible, handles novel structured-output shapes on request). The exam expects you to recognize both are valid — pick the service for standard tasks at scale, the LLM for flexible/novel shapes.

Implement speech solutions

TaskCapability
Audio → text, for an agent to act on spoken inputSpeech-to-text (recognition) workflow
Text → audio, for a spoken agent replyText-to-speech (synthesis) workflow
Speech as an agent's input/output modalityIntegrate speech into the agent, including custom speech models
Reason directly over an audio clip's contentMultimodal reasoning from audio input
Speak a reply in a different language than the inputSpeech translation via language models and Foundry Tools
Exam cue "Convert a recorded call into a transcript" → speech-to-text. "Read the agent's answer aloud" → text-to-speech. "The agent must both hear and speak in a live conversation loop" → speech integrated as an agent modality, not two separate one-off calls.
