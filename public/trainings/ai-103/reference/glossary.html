AI-103 · Reference

Glossary

The canonical AI-103 vocabulary. Every lesson and quiz option uses these names.

Platform & services

Microsoft Foundry
The unified platform for building, deploying, and managing AI apps and agents on Azure — portal, SDK, model catalog, and Foundry Tools in one place.
Foundry portal
The web UI where you deploy models, test prompts in a playground, and build/test agents without writing code.
Foundry project
The workspace inside a Foundry resource that an app's endpoint points at — the unit of work for deployments, agents, and connections.
Foundry SDK
The client library (azure-ai-projects, Python) for calling deployed models and agents from a lightweight client application.
Foundry Tools
Prebuilt AI capabilities available inside Foundry — Azure Speech, Azure Language, Azure Translator, Content Understanding — used instead of, or alongside, a raw model.
Foundry Agent Service
The managed service for building agents — a model plus instructions, tools, and knowledge that can plan and take actions to complete a goal.
azure-ai-projects
The Python package that is the current Foundry SDK. Provides AIProjectClient, get_openai_client(), and responses.create(...) for calling deployed models/agents.
DefaultAzureCredential
Keyless authentication using your signed-in identity (az login, managed identity) instead of a hard-coded API key.
Azure AI Search
The service that indexes and retrieves content for grounding — semantic, hybrid, and vector search over ingested documents.
Azure Content Understanding
Foundry's multimodal information-extraction service — pulls structured data and clean, grounded representations from documents, images, audio, and video.
Azure Language
Foundry Tools' purpose-built text-analysis service — entities, topics, summaries, sentiment/tone/safety detection — without custom prompt engineering.
Azure Speech
Foundry Tools' speech service — speech recognition (speech-to-text), speech synthesis (text-to-speech), and speech translation, including custom speech models.
Azure Translator
Foundry Tools' text-translation service — the named alternative to an LLM-powered translation flow.
Azure OpenAI / model catalog
Where foundation models (LLMs, SLMs, code models, multimodal, image-gen) are deployed and served through Foundry.
Azure Monitor
General Azure resource monitoring/alerting — distinct from AI-specific signals like drift or grounding-quality monitoring, which are Foundry-level concerns.

Model & generative concepts (Domain 2)

LLM (large language model)
A broad, capable model for chat, reasoning, and long-context generation.
SLM (small language model)
A leaner model for narrow, well-defined, cost/latency-sensitive tasks.
Multimodal model
A model that accepts and/or produces more than one modality — e.g. reasons over an image and a question together.
Embedding model
A model that converts text (or other content) into vectors for similarity search.
Token
The unit a model reads and generates — prompt length, output length, and cost are measured in tokens.
Temperature / top-p
Decoding parameters that control randomness — low temperature/top-p is deterministic and focused, high is creative and varied.
Retrieval-augmented generation (RAG)
Grounding answers in retrieved, current data at inference time instead of relying only on training data — prevents fabrication and stays current without retraining.
Fine-tuning
Changing a model's weights by training on labelled examples — distinct from RAG, which adds data at inference time without touching weights.
Fabrication
A model inventing facts not supported by any source — a named evaluation dimension apps must be checked for before shipping.
Agent
A deployed model plus role/goal, conversation-tracking (memory), a tool schema, and knowledge integration — able to plan and act, not just answer once.
Tool schema
The definition of which functions/APIs an agent may call and their contracts.
Conversation-tracking (memory)
How an agent remembers what was said in earlier turns of a dialogue.
Knowledge integration
Retrieval, search, or Content Understanding sources an agent can ground its answers on.
Single agent
One role, tools, and memory sufficient to complete a task end to end.
Orchestration
Coordinating multiple agents (multi-agent orchestration) or multiple models/flows (hybrid rules engines) to work together, beyond what any single agent or call can do alone.
Orchestrated multi-agent solution
Multiple specialized agents (e.g. researcher, writer, QA) collaborating and handing off work to complete one task.
Error analysis
Diagnosing the cause of a deployed agent's mistakes or error-rate spikes — part of the ongoing monitoring/evaluation an agent needs after deployment.
Semiautonomous workflow
An agent that acts largely on its own but under safeguards — e.g. an approval workflow before a risky action executes.
Multistep reasoning pipeline
A workflow where the model reasons across several intermediate steps before producing a final answer, rather than answering in one shot.
Prompt engineering
Tuning generation behavior by adjusting instructions and parameters.
Chain-of-thought self-critique
Having the model check and revise its own intermediate reasoning steps.
Observability (tracing, token analytics, latency)
Runtime signals — request traces, token usage, and latency breakdowns — used to understand a deployed generative system in production.
Drift
Gradual degradation in model answer quality as real-world input shifts over time — requires ongoing monitoring, not a one-time evaluation.

Planning, security & governance (Domain 1)

Managed identity / keyless credentials
Authenticating without a hard-coded secret, using the app's own Azure identity.
Private networking
Keeping model/agent traffic off the public internet, reachable only inside a private network.
Role-based access policies (RBAC)
Assigning least-privilege permissions for who can act on AI resources.
Quotas, scaling & rate limits
Capacity and cost controls per model/agent workload.
CI/CD integration
Wiring a Foundry project into a repeatable, reviewed deployment pipeline instead of manual portal changes.
Deployment options
Choices such as standard vs. provisioned throughput that shape a deployment's capacity and predictability.
Infrastructure design
Designing the Azure infrastructure an AI app or agent-based solution will run on, before any model is deployed — the first step under "set up AI solutions in Foundry".
Safety filters & guardrails
Controls that block or flag disallowed content before/after generation.
Content moderation
Ongoing classification of generated or ingested content for risk.
Safety evaluation
Checking that a generated answer doesn't contain unsafe or disallowed content, as part of the app's evaluation step.
Trace logging & provenance metadata
An auditable record of what an agent did and where its answer's content came from.
Approval workflow
A required human checkpoint before a risky agent action executes.
Oversight modes & tool-access controls
Constraints on what an agent is allowed to do autonomously, including which tools it may call.

Computer vision vocabulary (Domain 3)

Text-to-image generation
Creating a brand-new image from a text prompt.
Text-to-video generation
Creating a brand-new video from a text prompt.
Inpainting / mask-based editing
Modifying a targeted region of an existing image, distinct from generating a wholly new image.
Image captioning
Producing a concise or detailed description of one or more images.
Visual question-answering (VQA)
Answering a question grounded in what's actually shown in an image.
Alt-text / extended description generation
Generating accessibility-aligned image descriptions for assistive technology.
Video analysis
Processing and interpreting segments of a video via Content Understanding — the understanding-side counterpart to video generation.
Single-task vs. pro-mode (Content Understanding)
Single-task runs one narrow extraction job; pro-mode runs several coordinated extraction steps from one source in a single pass.
Indirect prompt injection (via images)
Text hidden inside an image's pixels that instructs a model to ignore its rules — a D3-specific responsible-AI risk.
Visual policy enforcement
Controls such as watermarking, prohibited-symbol flags, and brand-usage rules applied to generated visuals.

Text & speech vocabulary (Domain 4)

Entity / topic / summary extraction
Pulling structured meaning from text, via Azure Language or generative prompting.
Sentiment / tone detection
Scoring the emotional tone or sensitivity of text.
Speech recognition (speech-to-text)
Converting audio into a written transcript.
Speech synthesis (text-to-speech)
Converting text into spoken audio.
Speech translation
Producing speech or text output in a different language than the spoken input.
Custom speech models
Speech models tuned to domain-specific vocabulary (e.g. medical or legal terms).
Multimodal reasoning from audio
Reasoning about the content of an audio clip directly, beyond a plain transcript.

Information extraction vocabulary (Domain 5)

Vector search
Matching results by embedding similarity — meaning, not exact wording.
Semantic search
Re-ranking results for relevance using language understanding.
Hybrid search
Combining keyword (exact-match) search with vector search — the usual production default.
Enrichment
Custom or built-in skills that add structure to text, images, and layout during ingestion.
Optical character recognition (OCR)
Turning scanned, image-based text into searchable text — part of the RAG ingestion flow.
Field extraction
Copying a specific value (e.g. an invoice total) verbatim from a document.
Content Understanding markdown analyzer
A Content Understanding configuration that produces structured or markdown output shaped for downstream LLM reasoning.
